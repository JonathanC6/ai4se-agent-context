# ReAct 动态搜索对照

本轮使用 Labhuan claude-sonnet-4-6 和上一轮的 HTML、文本 PDF、Wayback/CDX 读取器。沿用相同的 10 道单源、10 道多源题、任务提示、独立 legacy-v1 裁判、温度 0、24 步、128K 预算，每题提交一次。每条轨迹从空历史开始。主对照取上轮固定候选组的最终轨迹。

## 实测结果

固定搜索 5/20，本轮 9/20。第 1、15、20、42 题由错转对，其余 16 题判分相同。这批题每题一轮，无法把查询改写、候选排序和恢复摘要的作用单独量化。

| 指标 | 固定候选、无摘要 | 动态查询、保留正常摘要 |
|---|---:|---:|
| 单源 · 多源 | 4/10 · 1/10 | 7/10 · 2/10 |
| 步数 | 122 | 113 |
| 已判分轨迹 token | 1,447,907 | 1,228,595 |
| 动作模型 · 网页提取 · 裁判 token | 776,027 · 648,124 · 23,756 | 898,791 · 303,609 · 26,195 |
| 实际记录 token，含中断重试 | 1,737,012 | 1,228,595 |
| 读齐标注页的题数 · 命中页数 | 5/20 · 11/30 | 5/20 · 11/30 |

轨迹 token 减少 219,312（15.1%），主要来自网页提取减少 344,515；动作模型增加 122,764。两轮实际记录用量相差 508,417（29.3%），其中含固定组中断后重跑的额外用量。16 题使用搜索，4 题仅浏览。最终轨迹的 45 个查询字符串互不相同，全部逐条核对缓存，相同查询的跨会话重放通过测试。过滤共移除 12 条结果，涉及 9 个不同 URL，来自 Hugging Face 和数据集镜像。更早的动态搜索组为 8/20，含题库暴露并使用不同的快照设置，仅供历史参考。

## 搜索设置

用户选择了公开网页搜索后端。与 PACE 的 Google 相比，动态查询和返回字段相近，但搜索引擎、排名和摘要可能不同。查询由 ReAct 发起，可改写或批量提交。按原查询字符串的 SHA-256 在本轮独立目录中永久缓存，跨题共享。agent 只能访问题目入口、已发现的搜索结果或页面链接。首次发出新查询时，由外部搜索客户端逐字查询，按返回排名解析标题、URL 和描述；描述取首段，最多 420 字符。过滤后返回最多 10 条。候选、原始问题、此前人工回放片段和参考答案均未被用来手动指定网页。

过滤针对可识别的 WebWalkerQA 镜像、题库数据及含原题和答案标记的转载。正常来源的标题、日期、人名、URL 路径和答案性摘要均保留。用原题文本辅助识别问答对，搜索客户端不使用参考答案。日志保存过滤 URL 与原因，统计以最终轨迹为准。此规则无法保证识别所有经过改写的转载。

在 PACE 目录执行。run 使用原模型凭据，搜索客户端使用 pending 取查询，并把形如 `[{"query":"…","results":[{"title":"…","url":"…","snippet":"…"}]}]` 的 JSON 输入 answer。运行前需要搜索客户端，已缓存的查询可离线重放。report 只核对本地缓存与轨迹。

```sh
PYTHONPATH=src .venv/bin/python -m benchmarks.webwalker_dynamic20 run
PYTHONPATH=src .venv/bin/python -m benchmarks.webwalker_dynamic20 pending
PYTHONPATH=src .venv/bin/python -m benchmarks.dynamic20_report
```
