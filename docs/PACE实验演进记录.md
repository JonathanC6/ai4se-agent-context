# PACE 实验演进记录

这份文档沿着一个问题更新：agent 已经读过很多材料，窗口却越来越小时，怎样保住回答需要的事实，并顺利交卷？每轮记录做了什么、遇到了什么困难、数据支持哪种解释，以及这个发现怎样影响下一轮。不同题单、窗口或工具的分数分别保留。

## 1. 从 PACE 的一次决策开始

一次搜索或网页访问形成一个历史块，包含动作目的、工具参数和观察。复现为每块保存原文，生成详细和简短摘要。下一步将问题和最近的观察编码，计算它们与旧块的余弦相似度，再根据相对权重和上下文压力决定展示全文、详细摘要、短摘要或只留下块号。最近两块优先展示全文。需要回看旧观察时，模型可以调用 Glimpse。

最初的课程实验使用冻结站点，便于复放。部分模型和网页服务与论文不同。早期语义编码使用远程服务，后来换成固定版本的本地 BGE-M3；动作、网页提取和裁判使用 Labhuan 的 Claude Sonnet 4.6。论文使用的摘要模型和裁判在当时的账号上不可用。我们逐步把工具能力、模型替代和评分版本写进每轮配置，先确认在哪里出现差异，再比较分数。[复现配置核对](../PACE/experiments/webwalkerqa-paper-check.md)

## 2. 从语义相关试到历史依赖

最早的改进想法来自写代码的场景：实现代码可能依赖更早出现的接口约束，两段文字的语义相似度却不高。于是让模型在输出动作时一起标注用过哪些块，组织下一轮上下文时，从相关块向前找依赖。后面加入 Anchor 保留关键原文，再用替代标记让旧版本退出活跃历史。

在早期 40 题冻结站点实验中，标准 PACE、只加依赖、再加 Anchor、再加替代分别答对 13、13、13、15 题。完整方案比标准版多答对 4 题，也少答对 2 题。逐题复放发现，有的“获益”题在摘要里已经包含答案，有的对裁判重评敏感。于是后续实验开始追问：实际提档的是哪一块？块里有没有新增的必要事实？[40 题四组消融](../DAG-PACE/experiments/ablation40.md) · [逐题归因](../DAG-PACE/experiments/ablation40-notes.md)

## 3. 为什么先修浏览，再调记忆

一次较大规模运行暂停时，PACE 的已评分部分只有 14/80。把网页轨迹与标注来源逐题对齐后，14 道读齐标注页的题答对 11 道，53 道完全没读到标注页的题只答对 2 道。单靠调摘要很难弥补从未取得的证据。我们补了历史快照和 PDF 读取，并把网页提取与历史压缩分开排查。[80 题审计](../PACE/experiments/webwalkerqa-audit80.md)

为排除题库泄漏，曾将每题固定为同一批候选，隐藏标题、摘要和 URL 路径。这样即使改写查询，模型也拿不到新候选。恢复动态搜索后，正常页面保留标题、摘要和 URL，同一查询复用结果，过滤题库镜像和转载标准答案。在早期同一批 20 题的 128K 窗口下，ReAct 从固定候选的 5/20 提升至动态搜索的 9/20；相同动态搜索下 PACE 为 7/20。下一轮开始固定浏览条件、单独缩小输入窗口，观察历史压缩能多走多少步。[搜索与窗口实验](WebWalkerQA实验进展.md)

## 4. 把窗口容量与 API 开销分开测

早期题单从 128K 缩到 16K 后，ReAct 从 9/20 降至 5/20，标准 PACE 仍为 7/20，完整 DAG-PACE 为 4/20。有些长轨迹确实靠压缩继续走，但多保留依赖和锚点也会占用有限的窗口。16K 下另一种压力公式从 7/20 变为 8/20，单源少对 2 题、多源多对 3 题。后续逐题分析都同时看增加和失去的题。

网关返回的单次输入量有时远高于实际可见提示的本地估值。我们将“发送前能否装进窗口”和“网关对已返回请求怎样计量”分别记录。在修订后的 6K 题单上，ReAct、标准 PACE、纯窗口压力 PACE 分别为 6/20、10/20、7/20，两种压力下的 DAG-PACE 都为 7/20。标准 PACE 有 64 步在全历史超过窗口时仍能执行。由此，除了总 token，还要记录提交数、超窗停止和压缩后实际继续执行的步数。[窗口预算与压力实验](WebWalkerQA窗口预算与压力公式实验.md)

## 5. 从“能展开原块”走到“展开后补了什么”

随后一版改用校准后的 horizon 20，在全文首次达到 90% 预算时启用多粒度组织。压缩启动后同时考虑窗口占用和进度。提交前检查草稿，按需展开历史块或重读保存的网页。在保留 80K 网关停止线时，这版只答对 2/20；改成网关用量只记录后答对 7/20、交卷 11 题。9 道未评分题都遇到动作格式问题，多数在首步就失败，还没有任何历史可压缩。[证据恢复实验](WebWalkerQA新版PACE证据恢复实验.md)

于是为动作增加 JSON 约束，首步两次格式错误时用原题搜索一次。覆盖检查器没有给出可执行目标时，允许再展开一个压缩过的网页块。这版答对 10/20、交卷 18 题。相对调整前，多出的 3 分来自上次没有交卷的第 1、2、59 题。6 次 Glimpse 都成功展开原块，其中 3 题在展开前已写对要点，另外 3 题展开后仍错。工具成功率与补齐缺失事实的成功率需要分开统计。[四道得分变化的逐题对照](WebWalkerQA标准与新版PACE逐题对照.md)

第 15 题回看了只有导航内容的官网块，仍无法确认基金总额。第 30 题找到专门的患者观点指南，全文可见时就答全了两个子问题。第 40 题已经读到正确日期，却因下一步最低需要 6,004 个可见 token，在提交前停止。这三题分别推动了本轮的目标选择、事实与来源绑定，以及最近观察的超窗回退。

### 压缩、回看和新增开销分别起了什么作用？

PACE-v2 在 15 题中启动多粒度压缩。10 题共 47 个决策步，按当步估值放入全文会超过 6K，压缩后成功执行。这是本轮直接测到的窗口收益。专门为极端超窗设计的“缩短最近观察”在线触发 0 次，常规四级压缩已经能容纳这些输入。

16 道题在准备提交时触发了 27 次自动补证，包括重新搜索 13 次、重读已存网页 14 次。模型主动和复核器自动调用 Glimpse 均为 0 次。27 次都返回了工具观察，只有 4 次为目标事实槽加入了新引语。复核器只把第 15 题的一次搜索标为“已解决”，它找到的是年度分配金额，仍然答错。按正式答案核对，这轮没有观察到补证带来独有的正确题。

## 7. 2026-11-26：修复动作接口后，五条失败轨迹能交卷了

首次运行中，ReAct 第 15 题与 PACE-v2 第 1、2、33 题都在中途连续返回无效动作。PACE-v2 第 407 题遇到搜索服务 HTTP 402。两组现在共用完整的动作示例和收尾逻辑。格式错误时可以提交最近的有效草稿，没有草稿时允许模型用可见证据直接回答。搜索错误会被记作工具观察。

保留另外 35 条轨迹，5 条从头补跑并交卷，全部判错。第 1、2 题的直接作答触及 1,600 个输出 token 的上限，两题各在原步追加了一次简短作答，问题与证据通过消息哈希核验。5 条补跑合计 535,412 token。ReAct 仍为 8/20，历史标准 PACE 为 10/20，PACE-v2 仍为 7/20。

这次暴露出两种“已有证据”的差别。首次运行的第 1 题有正确草稿，第 2 题读到了指定的声明页。重新运行时，两题只访问了首页，第二步就进入收尾，模型甚至续写了没有实际执行的网页访问。下一轮应重点检查动作失败时还能否沿着已发现的链接继续一次真实取证，同时保住已经写出的有效草稿。[三组逐题对照、失败原因与用量](WebWalkerQA动作接口补跑与三组对照.md)

## 8. 2026-11-27：区分网关流量和算法实际发送的输入

第 407 题的 ReAct 首步只增加 80 个字符，网关回报从 291,296 降至 382。我们核对了流水的加总、缓存字段和响应 ID，再用归档网页与原提示函数重建四组最终轨迹的可见输入。按这个口径，独立 v2 比同轮 ReAct 多 573,131，最大来源是动作调用（49.3%），其次是每块生成摘要（31.1%）。历史标准 PACE 则以摘要为最大来源（47.7%）。两版在各自这批轨迹上均未执行 Glimpse。

后续所有角色都同时记录本地输入、可见输出及网关回报。旧归档保留原值，分析开销时优先使用同轮可见输入，并单列重试、收尾和实际执行的工具。[用量复核与复算命令](WebWalkerQA用量复核.md)
